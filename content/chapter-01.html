1.1 从一句话到一串向量

把模型想成一间厨房：Tokenizer 把订单拆成可识别的食材编号，Embedding 把编号转换成模型能计算的向量，Transformer 再逐层加工。Token 不等于一个汉字，也不等于一个英文单词；实际切分由词表与分词算法决定。

文本经过模型对应的聊天模板与分词器，得到 Token ID。查找嵌入矩阵后，长度为 T 的输入成为 T × dmodel 的隐藏状态矩阵。BPE 是常见分词方案之一。位置关系也必须进入计算：例如 RoPE 通常旋转每层注意力中的 Q、K，而不是简单地给 Embedding 加一个位置向量。

1.2 Transformer：每一层在计算什么？

以常见的 Pre-Norm、Decoder-only 模型为例：归一化 → 因果自注意力 → 残差相加 → 归一化 → FFN/MLP → 残差相加。堆叠多层后，经过最终归一化与 LM Head，得到词表上的 logits。不同模型的归一化、激活与层内顺序可能不同。

Q · Query

我正在寻找什么？当前位置发出的查询。

K · Key

我可以如何被匹配？每个位置供检索的特征。

V · Value

我提供什么信息？被加权汇总的内容向量。

Q、K、V 都来自本层输入的线性投影；它们是训练得到的数值表示，“提问、标签、内容”只是帮助理解的类比。

Q = XWQ，K = XWK，V = XWV
Attention(Q,K,V) = softmax(QKᵀ / √dk + M)V

dk 是单个注意力头的 Key 维度；M 为因果掩码：可见位置为 0，未来位置为 −∞。Softmax 沿 Key 位置归一化。多头输出拼接并投影后，形成注意力子层输出。

Attention 跨位置混合信息，FFN 对各位置分别做非线性变换。残差连接保留信息通路；LayerNorm 或 RMSNorm 控制激活尺度。MHA 中每个 Query 头有对应的 KV 头；GQA 让一组 Query 头共享 KV 头；MQA 使用一组 KV 头。

原始 Transformer 论文同时包含编码器和解码器。本课程讨论常见自回归 Decoder-only 推理，不能把两种结构完全等同。阅读 Attention 论文 ↗

1.3 Prefill：并行读取输入

输入 Token 已全部已知，因此同一层内可同时处理多个位置，因果掩码保证每个位置只读取自己和之前的位置。层与层之间仍按依赖顺序执行。完整输入的 K/V 写入各层缓存；最后一个输入位置的 logits 用于采样第一个输出 Token。

标准稠密注意力中，长度 T 的 Prefill 注意力算术量约为 O(T²d)，这里 d 表示固定头数下的总注意力维度；投影和 FFN 另有开销。并行并不意味着没有二次增长的计算，也不要求一次处理完全部输入：第 2 章的 Chunked Prefill 会把它分轮完成。

1.4 Decode：用新 Token 接着生成

  1. 把刚采样出的 Token 连同正确的位置送入模型。
  2. 在每一层计算这个新位置的 Q、K、V，将 K/V 追加到缓存。
  3. 新 Q 读取历史和当前位置的 K/V，完成注意力，再执行该位置的 FFN。
  4. LM Head 给出新 logits，采样下一个 Token，直到 EOS、停止序列或长度限制。

logits 是未归一化分数。Temperature > 0 时可用 softmax(logits / temperature) 调节分布；Top-K 保留最高的 K 个候选，Top-P 保留累积概率达到阈值的候选集合。贪心解码直接选最大分数，常被接口用 temperature=0 表示。

注意“一步之差”。若输入长 T，刚输出 G ≥ 1 个 Token、且最后一个尚未回送模型，常规缓存中有 T + G − 1 个位置。容量规划常用 T + G 作保守近似。采样出一个 Token 与为它计算 KV 是两个时刻。

1.5 KV Cache：用显存换重复计算

在因果推理中，历史位置不会因为未来 Token 到来而改变，所以各层历史 K/V 可以复用。新位置只需要自己的 Q，历史 Q 不参与新位置输出的计算，因此通常不缓存 Q。缓存省去历史位置的投影、FFN 等重复工作，并没有省去对历史 K/V 的注意力读取。

MKV = 2 × L × HKV × dhead × b × ΣTi

L：层数；HKV：每层 KV 头数；dhead：头维度；b：每元素字节数；Ti：请求 i 已缓存的位置数；2 代表 K 和 V。适用于各层配置一致、完整注意力、没有共享的逻辑 KV 总量，不含权重、激活、元数据和分块余量。

动手算一算 / KV MEMORY

上下文增长，显存如何变化？

固定示例：80 层、头维度 128、BF16（2 字节），比较 64 个 Q 头下的不同 KV 头数。不是某张 GPU 的并发保证。

GiB = 2³⁰ 字节；10,000 Token 的 8 头示例为 3.052 GiB。多卡切分后的每卡占用取决于实际分片与复制方式。

1.6 把计算过程与体验指标连起来

阶段典型计算形态需要观察
Prefill多个已知位置，较大矩阵运算首 Token 时间 TTFT
Decode常规解码每个活跃序列每轮处理一个新位置平均 TPOT 与逐次 ITL

长输入 Prefill 常更偏计算密集，小批量 Decode 常更受权重和 KV 的搬运带宽限制；大批量、长上下文、模型架构与硬件会改变瓶颈，不能当作绝对规律。

TPOT = (t末 Token − t首 Token) / (Nout − 1)
E2E ≈ TTFT + (Nout − 1) × TPOT

仅当输出数 Nout > 1 时定义该平均 TPOT。TTFT 从同一请求起点计时，包含排队、预处理、Prefill、采样及相应传输；ITL 是相邻 Token 的到达时间间隔。若 E2E 还含最终响应收尾开销，上式为近似。

复习卡片

Prefill 处理已知输入；Decode 依赖刚生成的结果；每层 KV Cache 复用历史表示。
有 KV Cache，长上下文的 Decode 就是常数开销吗？

不是。标准完整注意力仍需访问增长的历史 KV。单个新位置的注意力算术量随上下文长度近似线性增长。

Prefill 并行为什么不会看到未来？

并行执行与可见性是两回事，因果掩码阻止位置 t 访问 t 之后的位置。

输入 1,000 个 Token，刚采样第一个输出，缓存多长？

常规自回归流程中是 1,000。第一个输出尚未送入下一次前向计算，因此没有它的 KV。

术语速查

Hidden State / 隐藏状态
每个位置在当前层的向量表示。
Autoregressive / 自回归
根据已有序列预测下一个 Token，再将结果纳入后续条件。
LM Head
将最终隐藏状态映射到词表分数的输出层。
KV Cache
各层已处理位置的 Key 与 Value 缓存。
Compute-bound / Memory-bound
主要受计算吞吐限制 / 主要受数据搬运带宽限制。
